## [0.1.0] - not yet published

First version. It renders Excalidraw files to the SVG that Excalidraw 0.18.1's
`exportToSvg` produces, byte for byte, without a browser.

### Added

- `parse_scene` reads `.excalidraw` JSON. It drops deleted elements, fills in what old
  files leave out the way the official `restore` does, ignores unknown fields, and
  reports damaged input as a `ParseError` that names the element.
- `export_to_svg` writes the SVG: canvas size, 10px padding, background, element order,
  frame titles and clipping, `<a>` links.
- Elements: rectangle, diamond, ellipse (with rounded corners), line, arrow (straight
  or curved, all twelve arrowhead styles), freedraw, text (also bound to shapes and
  arrows), image (crop, flip, rounded corners), frame and magicframe.
- Styles: stroke and background colour, `hachure`, `cross-hatch`, `solid` and `zigzag`
  fills, stroke width and style, roughness, opacity, rotation, seed.
- `FontMode::Url` writes the `@font-face` rules the official export falls back to when it
  cannot fetch the fonts; `FontMode::None` leaves them out.
- Elements that can't be drawn (embeddable, iframe, elbow arrows, unknown types) fail with
  `UnsupportedPolicy::Error` or are skipped with a warning, as the caller chooses.
  Other things that won't match the official export, such as `seed: 0`, also warn.
- `perfect-freehand` 1.2.0's `getStroke`, ported and compared bit for bit.
- `excalidraw2svg` command (`-o`, `--no-fonts`, `--strict`) and a gallery page that sets
  each scene beside the official output.
- Tests that compare with the official package: 1176 scenes, 322 freehand strokes, 50
  `restore` cases, and V8's `hypot`, `atan2` and `parseFloat`. Expected values are
  generated by `scripts/gen_fixtures.mjs` from `@excalidraw/excalidraw` 0.18.1 and
  `perfect-freehand` 1.2.0, pinned by `scripts/package-lock.json`.
- CI on Linux, macOS and Windows, and a job that regenerates the fixtures and requires
  them to be unchanged.

### Known differences from the official export

See "和官方结果的差异" in the README. In short: fonts are referenced or left out, never
embedded; the unsupported elements above are not drawn; `Math.pow(x, 3)` is correctly
rounded where V8 depends on the platform; a frame title is measured with an estimate
unless the caller passes a measuring function.

### Known issues

- A closed `line` with a pattern fill can differ from the official output by about
  `1e-15` in a rotation centre: rough.js changes the points it is given in place and
  later calculations read them. A fix is in progress.
- The `roughjs_464` option this project needs is in a moon_rough release that is not
  published yet, so the CI fails until `moon.mod` points at that release.
